## Decisions

- D1. v2 contracts location: LlmContextV2 / ProposedBeat / ExtractionResultV2 /
  ExtractorV2 / MockExtractorV2 go in app/services/extractor_v2.py, mirroring the
  v1 extractor.py that holds LlmContext + ExtractionResult + Extractor + Mock in
  one file. TurnRequestV2 / TurnResultV2 go in models_v2.py (wire DTOs, mirrors
  v1 putting TurnRequest/TurnResult in models.py).
- D2. Entity linking: ProposedBeat carries entity names (character/theme/setting).
  DeltaApplier resolves each name against existing project entities by exact
  match, creates the ones that dont exist, then links via a new link_to_beat
  method on each entity repo. This gives the core "writer mentions Sarah, Sarah
  gets tracked and linked to the beat" behavior.
- D3. Commit local waves, no push. The branch (feature/services-orchestrator) is
  already PR #53 for the catalog wave; growing it vs a stacked PR is the user's
  call when back, so hold all pushes.
- D4. router_v2 path needs a real db (v2 repos are Sql-only). Tested over HTTP via
  httpx ASGITransport with get_db overridden to the test session. No InMemory v2
  repos built (would be a large separate effort, see W4).
- D5. v2 DI lives in app/core/dependencies_v2.py (composition root for a turn),
  kept separate from the v1 dependencies.py that #52 rewired.
- D6. Added a ruff per-file ignore for B008 on app/api/* and dependencies*, since
  fastapi puts Depends() in argument defaults by design. The v1 router.py was
  already tripping B008 22 times unaddressed; this makes the route layer consistent.
